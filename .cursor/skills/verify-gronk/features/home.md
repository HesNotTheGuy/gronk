# Home

Home is the landing pad. It states the Chat vs Build rule, offers those two buttons, shows account / CLI / model status, and draws the activity heatmap. It does not list folders or sessions; those catalogs live on Chat and Build.

## Sub-features

- `home-open` shows the Home landing (kicker `Home`, heading `Grok on your desktop`).
- `home-chat` goes to Chat browse from the Home hero `Chat` button.
- `home-build` goes to Build browse from the Home hero `Build` button.
- `home-heatmap` shows `.calendar-panel` (Activity). A day click lands on Build with that day filtered.
- `home-meta` shows Account, CLI, and Model on `.home-meta`.
- `home-auth-overlay` — when the CLI is not signed in, `.auth-overlay` covers Home and cannot be dismissed.

## How to get to it (user POV)

- Launch Gronk. The default surface is Home.
- Click the Gronk mark in the sidebar (`title="Home"`).
- Command palette: `Go to Home`.

## Driving it with control-gronk

Preconditions:

- `control-gronk.mjs doctor` exits 0.
- Instance userData is under `$TMPDIR/gronk-verify/`.
- You have not called this a Chat or Build proof.

- **See Home.** Wait for the landing heading. Run `control-gronk.mjs wait --text "Grok on your desktop"`. The document contains `.home-view` and a `.home-kicker` whose text is `Home`. The topbar kicker is also `Home`.
- **Read the overlay.** Run `control-gronk.mjs eval --js "!!document.querySelector('.auth-overlay')"`. If `true` and there is no `Continue to app` button, stop the click-through. Snapshot and screenshot the overlay. Home is underneath; a user cannot press Chat or Build. That is `home-auth-overlay`, not a failed Home mount.
- **Continue when signed in.** If the overlay offers `Continue to app`, run `control-gronk.mjs click --text "Continue to app"`. The dialog is gone. `.home-view` is interactable.
- **Hide onboarding if it covers the hero.** Run `control-gronk.mjs click --text Hide --within .onboarding` when `aria-label="Getting started"` is present. The checklist leaves; Home remains.
- **Open Chat from Home.** Run `control-gronk.mjs click --text Chat --within .home-actions`. Topbar kicker becomes `Chat`. Main shows kicker `Chat` and heading `Talk with Grok`.
- **Return Home.** Run `control-gronk.mjs click --selector button.brand`. `button.brand` has `aria-current="page"`. Heading is again `Grok on your desktop`.
- **Open Build from Home.** Run `control-gronk.mjs click --text Build --within .home-actions`. Topbar kicker becomes `Build`. Main kicker is `Build`.
- **Heatmap.** From Home, confirm `.calendar-panel` and the group `Show activity for`. Do not treat an empty `No activity to show yet.` as a failure on a fresh userData dir.
- **Proof.** Run `control-gronk.mjs snapshot --path artifacts/verify-gronk/home.aria.txt` and `control-gronk.mjs screenshot --path artifacts/verify-gronk/home.png` on Home after the overlay (if any) is understood. Artifacts must show the Home kicker or the auth overlay that is blocking it. They must not show a Folders heading or a Build sessions heading.

## Gotchas

- Fresh userData almost always opens `.auth-overlay`. There is no Skip. The effect that opens it re-opens it if you try to hide it while unsigned-in.
- `Chat` and `Build` exist on Home **and** in `nav[aria-label="Main"]`. A click without `--within .home-actions` is the wrong entry point for `home-chat` / `home-build`.
- Onboarding uses `.home-kicker` with the text `Getting started`. Assert the Home kicker text `Home`, not the class alone.
- Home must not grow a `.browse-grid` of folders or sessions. If you see `Folders` or `Build sessions` on Home, the map is stale or the landing-pad change regressed — do not edit this file to match the regression.
- Clicking a heatmap day is defined to switch to Build. That is a Home entry into Build, not a Home catalog.
- `npm run test:visual` Home shots are the fake gallery. They are not this proof.
